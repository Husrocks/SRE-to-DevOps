Essential DevOps Commands Reference

Copy and use these commands when practicing Docker, K8s, and Git!

Git & GitHub Workflow Version Control

Check status and staged files:

git status

Commit changes with Conventional Commit format:

git commit -m "feat: add chaos simulator"

Push to GitHub main branch:

git push origin main
Docker Container Commands Containers

Build Docker image with tag:

docker build -t myapp:1.0 .

Run container in background with port mapping:

docker run -d -p 8080:80 myapp:1.0

View running containers and live logs:

docker ps
docker logs -f <container-id>
Kubernetes (kubectl) K8s

Apply all manifests in folder:

kubectl apply -f k8s/

View pods, services & autoscalers:

kubectl get pods,svc,hpa

Describe a pod to inspect restart reasons:

kubectl describe pod <pod-name>
GitHub Actions CI/CD CI/CD

on: [push, pull_request]

Workflow file location:

.github/workflows/*.yml

Auto deploy to Pages:

uses: actions/deploy-pages@v4

              Top 6 Problems Engineers Face in GitHub DevOps & How to Solve Them
            

            
These are the most common production issues experienced in real engineering teams.

          


          

            
            
            

              

                PROBLEM 01
                Permissions
              

              
403 Resource Not Accessible by Integration

              
By default, GitHub gives workflows read-only access. If your pipeline tries to publish to GitHub Pages or comment on a PR, it immediately crashes with HTTP 403.

              

                permissions:

                  pages: write

                  id-token: write
              

            


            
            

              

                PROBLEM 02
                Security
              

              
Leaking Secrets in Console Logs or Commits

              
Developers accidentally echo secret tokens in bash scripts, or commit a .env file. Bots on the public internet scrape GitHub commits within 3 seconds to steal keys!

              

                # Always use GitHub Secrets & secret masking

                env: API_KEY: ${{ secrets.MY_API_KEY }}

                # Enforce .gitignore on all .env files
              

            


            
            

              

                PROBLEM 03
                Performance
              

              
Slow Builds & Wasted Runner Minutes

              
Running npm install from scratch on every run downloads 500MB over the network, stretching 30-second builds into 8-minute builds and exhausting team quotas.

              

                - uses: actions/setup-node@v4

                  with:

                    cache: 'npm' # Cuts build time by 80%!
              

            


            
            

              

                PROBLEM 04
                Concurrency
              

              
Deployment Race Conditions

              
When two developers merge PRs back-to-back, two deploy workflows run simultaneously, causing race conditions where the older commit can overwrite the newer release.

              

                concurrency:

                  group: 'pages'

                  cancel-in-progress: false
              

            


            
            

              

                PROBLEM 05
                Reliability
              

              
Flaky Tests & Network Timeouts

              
Tests that depend on external internet APIs fail randomly when third-party servers rate-limit or experience hiccups, blocking valid pull requests.

              

                # Mock all external network calls in unit tests

                # Use retry logic for network actions
              

            


            
            

              

                PROBLEM 06
                Infrastructure
              

              
Runner Disk Space Exhaustion

              
GitHub hosted runners provide ~14GB of free disk space. Building large Docker images or deep node_modules trees causes sudden No space left on device errors.

              

                # Use slim base images (e.g., alpine)

                # Clean up dangling images after build
